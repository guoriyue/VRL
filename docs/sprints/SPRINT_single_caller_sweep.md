# SPRINT: single-caller function sweep

Sequel to `SPRINT_repo_hygiene_sweep.md`, same discipline, one question:
which functions exist only to split a concept that has one caller?

AGENTS.md forbids extracting a helper with a single caller, and lists what a
one-caller function may legitimately be: a lazy-import boundary, a protocol or
public-API facade, a framework adapter, a test fake, a cross-family uniform
shape, or a concept-naming extraction from a long flow. Everything else with
one caller is a concept split and is inlined.

## Method

An AST scan of `vrl/` (scratch, not committed) listed every function whose name
is defined once and referenced once outside its definition. 794 hits. Narrowed
to the shape the rule is about -- private, undecorated, caller in the same file
-- leaves 571; of those, 190 are at most 15 lines with no test reference and are
read first. Nothing is inlined from the list alone: every row below was read at
the body and at the call site.

`kept` rows are grouped when several functions are kept for the same reason;
the group names its members.

## What was not read, and why that is the boundary

- **Private single-caller functions of 16-30 lines that a test names** (about
  40, not listed): row 44's reasoning applies unchanged -- a pinned unit is a
  seam someone asked for, and inlining it deletes or re-points the test.
- **Private single-caller functions over 30 lines** (about 170): at that size
  a body is a subprogram, not a paragraph of its caller. The rule the operator
  stated targets the forwarding helper ("why add this function, it's only
  called once"), and rows 52-54 show that even at 16-30 lines the exceptions
  already dominate. These were not read for this sweep; the scan listing in
  the session scratchpad names them if a later pass wants to.
- **Public single-caller functions**, decorated functions, and cross-file
  single callers: module boundaries and public API are the keep-list's own
  categories.
