## 0. 为什么是这个目标

三个月里 Anima 上所有 RL 目标都卡在同一模式：奖励排的是风格/噪声（判官），或 base 已
经会了（标签遵循 0.92）。GenEval 是唯一一个**base 明显弱、奖励又是规则打分**的轴：

| 任务 | Anima base（553 题，OWLv2+CLIP 近似，2026-09-03） | 备注 |
|---|---|---|
| single_object | 0.988 | 饱和 |
| two_object | 0.798 | |
| colors | 0.894 | |
| **counting** | **0.400** | |
| **position** | **0.450** | |
| **color_attr** | **0.390** | 属性绑定 |

先例：Flow-GRPO 在 SD3.5-M 上用同一奖励 0.63 → 0.95（32 卡、48 prompt × 24 图/epoch、
β=0.04、global_std、lr 3e-4、LoRA、clip 1e-4、EMA）。

## 1. 奖励：`geneval_owl`（进程内，OWLv2 + CLIP）

官方 GenEval 评估器（mmdet Mask2Former Swin-S COCO + CLIP）本机没装，Flow-GRPO 通过
独立 conda 环境 + HTTP reward-server 接。我们用 09-03 已跑过的近似实现：

- 检测：`google/owlv2-base-patch16-ensemble`（开放词表；对动漫画风比 COCO 训练的
  Mask2Former 更有希望，G0 门会验证），per-class NMS 0.5，阈值 0.2。
- 颜色：`openai/clip-vit-large-patch14` 对检测框裁片做 10 色零样本分类。
- 位置：官方 GenEval 的框中心偏移 + 0.1 尺寸容差规则。
- 打分：`geneval_owl_strict` = 全部条件满足才 1（= 官方 GenEval 定义）；
  `geneval_owl` = 满足条件数 / 总条件数（部分分，减少全 0 / 全 1 的零 advantage 组；
  Flow-GRPO 的 reward-server 同样训练用部分分、报告用 strict）。
- 确定性：无采样，同图同分；可复现的 tagger 式奖励，不是判官。
- 放置：`distributed.resources.reward.device` 默认 `trainer`，模型常驻 trainer GPU
  （OWLv2-base + CLIP-L fp32 ≈ 2.3 GB；trainer 峰值 12.6 GB + rollout 7 GB，不用 parking）。

已知局限（写在这里，不写进奖励）：检测器是照片域训练的，动漫物体可能漏检/误检；策略
可能学会"把物体画得更像照片"来讨好检测器。护栏见 §4。

## 4. 门（按顺序，写死在训练前）

- **G0 奖励在动漫域的有效性**：用进程内模型给 553 张 base 图打分，抽 24 张判 1 + 24
  张判 0 做人工核对，检测器判断与人眼一致 ≥ 90%；否则调阈值或换检测器，不进训练。
- **G1 策略能不能动**（10 次更新）：KL 惩罚要脱离 target C 的 <1e-3 带、训练 reward_mean
  要上升。两者都不动 → 停，问题在优化器步长而非奖励，不继续堆步数。
- **G2 主跑**：每 25 次更新存 checkpoint，held-out 553 动漫题 seed 对齐（同 manifest、
  seed 7777、base 与 checkpoint 逐题配对）。成功 = strict 总分显著高于 base（prompt 级
  自举 CI 不跨 0），且 position / color_attr / counting 至少一项 +0.1。
- **护栏**（任一破 = 不算成功）：锐度 median 不低于 base 的 90%；奖励翻转样本（base 0 →
  ck 1）抽 24 张人工看，"检测器被骗"（物体变照片风、碎片、重复贴图）≤ 4 张；
  `wd_tagger` 在 target C 的 170 行 held-out 上不下降（与训练奖励不相交的指标）。

### 6.5 为什么 G2 的曲线看不出趋势，改做固定 prompt 过拟合探测（2026-09-07 13:50）

G2 跑到 epoch 42 停止（checkpoint-40 保留）。训练奖励按十步分段 0.730 / 0.721 / 0.770 /
0.742，held-out ck30 = base。原因是实验设计的分辨率不够，而不是步数：

- 每步随机抽 16 条 prompt，prompt 间部分分 sd = 0.252 → 每步均值噪声 ±0.063；按 Flow-GRPO
  的节奏折算，我们每步预期增益 0.001–0.003，信号比噪声小 20 倍，曲线**结构上**看不出趋势。
- 553 题 held-out 的 CI 半宽 ±0.021，一次 25 分钟；40 步累计预期增益 0.01–0.03，在分辨率以下。

改用"固定 prompt 过拟合探测"（同 DROID 的 can-the-curve-move 配方）：从 base 评估里挑 8 条
base 半对的难题（3 counting / 3 position / 2 color_attr，`outputs/probe_overfit_8_anime.jsonl`），
每步都训这 8 条 × 16 张（128 张/步），20 步，`outputs/anima_geneval_owl_probe_overfit8`。
prompt 不变 → 训练奖励本身就是评测（噪声 ±0.02）。判据：20 步内 reward_mean 明显爬升
（≥ +0.15）= 管道通、只是预算问题；爬不动 = 管道有问题（奖励噪声 / advantage / 步长），
再往 50k prompt 上堆步数没有意义。

**过拟合探测结果（15:18 停止）**：10 步 reward_mean 0.690 0.663 0.652 0.706 0.708 0.664 0.698
0.678 0.697 0.663——8 条固定题上**零斜率**。这排除了"预算不够"：正常的 GRPO 在固定题上 10
步内应开始记住。结合历史：平价修复（2026-08-28）之后 Anima 上没有任何奖励曲线动过（§3 干净
对照、target C、本 sprint）；修复前的 run 9 训练奖励曾**单调下降**且显著。

### 6.6 机器冒烟：稠密奖励能不能爬（2026-09-07 15:19 启动）

把奖励换成 `image_sharpness`（拉普拉斯能量，确定性、稠密、CPU），同样 8 条固定题 × 16 张、
10 步（`outputs/anima_sharpness_probe_overfit8`）。这是 Flow-GRPO / DDPO 自己的
compressibility 式冒烟：策略必定能提高锐度。判据：10 步内 reward_mean 明显上升 = GRPO 机器
正常，GenEval 的问题在信噪比 / 探索强度（noise_level 0.3 vs Flow-GRPO 0.7，128 vs 1152
样本/步）；不上升 = Anima 的 GRPO 管道本身有问题，先修管道。

**锐度冒烟结果（16:08 停止）**：6 步 0.605 0.537 0.558 0.581 0.552 0.518——稠密确定性奖励
在固定题上也**不爬**。读了损失和 SDE 对数概率（`vrl/algorithms/grpo/continuous.py`、
`vrl/math/denoise/flow_matching.py`）：与 Flow-GRPO 同式，EDM→RF 的 sigma 换算推导正确；奖励与
轨迹的拼接按 `sample_rows` 顺序、chunk 按索引排序，结构上没问题；`window_size: 0` = 全部 20 步
SDE，"随机选中确定性步"假设不成立。

**校准后的解释**：Adam 下每步参数位移 ≈ lr，与梯度大小无关；梯度里信号占比低时就是随机
游走——图像大幅变化（19.5/255）而奖励不动，正是这个现象。`ppo_epochs=1` + 流式累积 =
每个 rollout batch 只有 **1 次**优化器步。仓库自己的 Flux 验证
（`info/SPRINT_flux_algo_validation_curves.md`）结论完全一致：ppo_epochs=1 四条曲线全平，
改 4 机制才激活，"根因不是 epoch 数，是 ppo_epochs=1 的零漂移 + per-step 小梯度"。
Anima 所有 run 都是 ppo_epochs=1（流式累积强制）。

### 6.7 ppo_epochs=4 锐度探测（16:09 启动）

同 8 条固定题 × 16 张，`actor.gradient_accumulation_steps=0`（非流式，整批常驻）+
`actor.ppo_epochs=4`（每批 4 次优化器步，clip 3e-3 开始咬合），10 步，

### 6.11 根因确认：`noise_level` 0.3（2026-09-07 20:19）

同一模型、同一奖励、同一 8 条固定题、同一配方，只改 SDE 探索噪声：

| 探测 | n | 首 → 末 | delta | 标准误单位 | 斜率/步 |
|---|---|---|---|---|---|
| **Anima noise 0.7** | 10 | 0.669 → **0.844** | +0.175 | **+7.7** | +0.0199 |
| Anima noise 0.3 | 6 | 0.605 → 0.518 | −0.087 | −3.0 | −0.0105 |
| SD3.5 noise 0.7 | 10 | 0.942 → 0.973 | +0.031 | +4.4 | +0.0028 |

逐步：`0.669 0.689 0.690 0.739 0.777 0.774 0.772 0.814 0.832 0.844`，十步里九步不降。

**机制**。流匹配采样本身是确定性 ODE，没有可打分的动作。flow_grpo Eq.9 把它改写成边缘
分布相同的 SDE：每步注入 `std·sqrt(-dt)·ε`，均值由模型输出决定，于是每步有对数概率、组内
样本有轨迹差异。`noise_level` 缩放这个 std，是**探索温度**。

策略只控制均值，所以只有"由注入噪声造成的"那部分奖励差异可以归因给策略。每个样本还各自
抽一个初始 latent，那部分差异与 `noise_level` 无关。把噪声从 0.7 压到 0.3 只压缩了可归因
的那一半，advantage 于是主要反映"谁的初始 latent 运气好"。同时每步得分函数是
`ε/noise_scale × ∂均值/∂θ`（`vrl/math/denoise/flow_matching.py`），噪声越小梯度越大——
更大但更没信息量的梯度。从收敛模型出发的随机游走会让任何质量指标单调变差，所以症状是
缓慢下滑而不是持平。

**来源**。`SPRINT_anima_rl_5090.md` run 1 测到 rollout 得分 0.20–0.22 而同 prompt 评测 0.69，
正确归因到 SDE 噪声，但把它当成"rollout 被过度加噪"要修，run 9 遂一次性改了三项（20 步
rollout、noise 0.3、16×16 批量），噪声一项从未被单独隔离。run 9 奖励随即从 0.637 单调掉到
0.452，被记为"关于奖励的真实负面结果"。同一份文档当时已经写明"rollout 奖励与评测质量是
两个尺度，绝不能互比"——rollout 本就不该像评测图，噪声就是被打分的动作。

**波及范围**。Anima 是全仓库唯一使用 0.3 的 preset（其余家族 0.7 或 1.0）。2026-08-18 之后
的每一条 Anima run 都带着它：AnimeReward、PickScore、Luna/codex 判官、OCR、精确人数、
tag adherence、以及本 sprint 的 GenEval。这些负面结论不能再当作"目标不行"或"奖励不行"的
证据。修复：`experiment/anima_preview3/online_grpo` 的 `noise_level` 改为 0.7 并把测量写进注释。

**跨家族与历史记录的交叉印证。** 仓库里唯一起势过的图像 GRPO 曲线是 SANA aesthetic
（2026-07-11 调度器修复后 4.26 → 4.29 → 4.32，约三个 checkpoint），同期记录还写了
"SD3.5-medium 开箱即用"。解析这两个 recipe，探索噪声都是 **0.7**。Anima 上最接近成功的是
平价修复后的干净对照 run，ck10 held-out +0.0061（z=+0.52），文档自称"诚实的零结果"。

更强的印证来自 `SPRINT_anima_rl_5090.md` 自己：它记录了随机游走的指纹却未能命名。三次
目标不同的 run —— 只用 AnimeReward、AnimeReward + 75 倍 KL、PickScore 主导（AnimeReward
仅 1/4 权重）—— AnimeReward 的下降速率几乎相同（−0.0388 / −0.0311 / −0.0337）。原文写道
"某种东西在退化策略，**与它在优化什么无关**"，并称这个发现比 reward hacking 的解释更重要。
梯度若携带目标信息，退化速率必然随目标改变；不随，即说明梯度不含目标信息。三次 run 全部
使用 noise 0.3。

## 7. 为什么 Anima 一直训不动：三个机器缺陷的链条

把两份 anima sprint 和今天的测量拼起来，答案不是"某个 bug"，而是**三个互相独立的机器
缺陷，发现于不同时间，从未同时正确过**：

| # | 缺陷 | 存在期 | 实测效应 | 发现于 |
|---|---|---|---|---|
| 1 | 平价/重要性比率坏掉（torch_compile × 批形状，log-prob 漂移 0.203） | 2026-08-28 之前的全部 LoRA GRPO run | 首步 `pre_update_active_clip_fraction` 恒 7.0–7.3%，修后 0.00% | target_search §1 |
| 2 | 最后一个去噪步永远拿不到梯度（`timestep_fraction: 0.99`，20 步时 `int(20×0.99)=19` → 索引 0..18） | 至 5090 sprint 实验 D | grad_norm **5.1 倍**、approx_kl **9.9 倍**；驱动目标从显著下降（t=−8.40）变为持平（t=+0.84） | 5090 sprint 实验 D |
| 3 | 探索噪声 `noise_level: 0.3`（全仓库唯一低于 0.7 的 preset） | 2026-08-18 至 2026-09-07 | 固定题上 0.3 为 −3.0 标准误，0.7 为 **+7.7 标准误** | 本 sprint §6.11 |

**关键在于它们错开的时间窗。** 缺陷 1 在 08-28 修好，缺陷 3 在 08-18 引入，所以修好平价
之后曲线依然平——第二个缺陷接管了。5090 sprint 的实验 D 修好了缺陷 2，把下降变成持平，
但它跑在 noise 0.3 上（继承自 run 9），被缺陷 3 封在"持平"。原文由此得出
"机制修好了，剩下的阻碍是奖励"，并转而去找更好的奖励和目标——接下来三周的 OCR、精确
人数、tag adherence、以及本 sprint 的 GenEval，全部建立在这个错误结论之上，且全部带着
缺陷 3。**每一个"这个目标/奖励不行"的结论，都是在坏掉的机器上测出来的。**

**今天的探测自己也重新打开了缺陷 2。** preset 的 `timestep_fraction` 是 1.0（实验 D 的
修复），而本 sprint 的所有启动脚本都覆盖成 0.25（来自 target_search §11.6 的提速建议）。
`timestep_selection=random` 使最后一步不再被系统性排除，但每次更新仍只有 20 步中的 5 步
拿到梯度，而实验 D 测得被排除的那一步承载了大部分梯度。因此 §6.11 的 +7.7 标准误是在
缺陷 2 半开的情况下取得的，很可能低估了正确配置的效果。

固定题 GenEval 探测按上述两档依次跑：先 `noise 0.7 / tf 0.25`（与 0.3 那次单变量对照），
完成后自动接 `noise 0.7 / tf 1.0`（三个缺陷全修的第一次配置）。

### 7.1 第四个 Anima 专有离群项：LoRA 缩放（待验证）

扫描全部 24 个模型 preset 的 `alpha/rank`：

| 家族 | rank | alpha | 缩放 |
|---|---|---|---|
| **cosmos/anima_preview3** | 32 | **16** | **0.50** |
| 其余 23 个（sd3_5、flux、sana、wan、cosmos3、predict2_5、qwen_image …） | 16 或 32 | 32 或 64 | **2.00** |

Anima 是唯一一个缩放低于 2.0 的家族，preset 里没有注释、两份 anima sprint 里也没有任何
讨论，值随 2026-07-18 的家族重组提交进来。LoRA 的输出增量是 `(alpha/rank)·B·A·x`，而 Adam
的参数步长与梯度大小基本无关（≈ lr），所以在同一个名义 lr 下，Anima 每次更新对模型输出的
改变量比其他家族小 **4 倍**。这与 `noise_level` 是同一种形态：全仓库唯一的、无据可依的
离群设置。

尚未验证，且不宜与噪声/timestep 的实验混在一起。排在 §6 两档固定题探测之后：若
`noise 0.7 + tf 1.0` 仍然平，下一个单变量就是 `model.lora.alpha=64`。

### 7.2 顺带确认：`strided` 在 `timestep_fraction < 1` 时确实系统性排除最后一步

`OnlineTrainer._train_timestep_indices(20, 0.25, "strided")` 返回 `[0, 4, 8, 12, 16]`，
最后一步 19 永不入选；`(20, 0.99, "strided")` 返回 19 个索引 0..18，同样排除 19。改用
`"random"` 后最后一步入选比例实测 0.25，即不再系统性排除，但每次更新仍只有 5/20 步拿到
梯度。`strided` 是 `actor.timestep_selection` 的默认值，任何 `timestep_fraction < 1` 且未
显式选 `random` 的配方都带着缺陷 2。

### 7.3 固定题 GenEval 探测，噪声 0.7（2026-09-08 01:2x）

`0.688 0.681 0.691 0.643 0.696 0.678 0.643 0.680 0.692 0.671`，斜率 −0.0007，
首末差 +0.005（+0.2 标准误）。**平。**

三条固定题探测放在一起，全部同模型、同 8 条题、同 `timestep_fraction 0.25`：

| 奖励 | 噪声 | n | 首 → 末 | 标准误单位 | 斜率 |
|---|---|---|---|---|---|
| GenEval | 0.3 | 10 | 0.690 → 0.663 | −1.2 | +0.0004 |
| GenEval | **0.7** | 10 | 0.688 → 0.671 | **+0.2**（首末）/ 斜率 −0.0007 | 平 |
| **锐度** | **0.7** | 10 | 0.669 → 0.844 | **+7.7** | +0.0199 |

**噪声修好之后，差异被干净地隔离到奖励本身**：同一台机器同一组题，锐度可训，GenEval
不可训。最可能的原因是奖励的粒度与可探索性——锐度是像素的连续函数，任何微小图像变化都
平滑改变分数；GenEval 是检测器阈值判定，组内分数只取"满足条件数／总条件数"的少数离散值，
而且"三个苹果变四个"需要一次全局协调的改变，不是每步小扰动能可靠命中的方向。

`timestep_fraction 0.25` 仍让缺陷 2 半开，故不下最终结论；`tf 1.0` 那档随后自动启动。

### 7.5 奖励为什么推不动：粒度为主，迁移为辅（`reward_transfer_probe.py`）

同一批初始 latent，每个渲染两次：SDE rollout（噪声 0.7，训练分布）与确定性 ODE（干净，
评测分布），两边都用训练奖励打分。GRPO 只消费**组内排序**，所以关键量是两个排序的
Spearman 相关。8 条题 × 16 个 latent：

| 量 | GenEval | 锐度（正对照，可训） |
|---|---|---|
| 排序相关 rho（加噪 vs 干净） | **+0.164** ± 0.113（t=+1.44，逐题 −0.27…+0.63） | **+0.369** ± 0.057（t=+6.45） |
| 16 样本组内的**不同奖励取值个数** | **2, 2, 2, 3, 3, 3, 4, 4** | 连续，16 |
| 分数水平（加噪 vs 干净） | 0.658 vs 0.642 | — |

两条结论，强度不同：

1. **粒度（结构性事实，不需要统计）**：GenEval 的组内奖励只有 2–4 个不同取值，计数题只有
   **2 个**——16 个样本被切成两半，advantage 退化成二值。梯度每次更新只能说"往这一半靠"。
   锐度是像素的连续函数，16 个样本 16 个不同值。这是可训与不可训的第一位原因。
2. **迁移（暗示，n=8 不足以定论）**：加噪排序与干净排序的相关，GenEval 只有锐度的一半，
   逐题还会翻负号；两者之差 +0.205 ± 0.136（t=1.51），方向符合假设但不显著。注意**分数
   水平迁移得很好**（0.658 vs 0.642），坏掉的恰恰是排序，而排序正是 GRPO 唯一消费的东西。

**据此的下一步不是换目标，是把这个目标的奖励变稠密。** GenEval 的空间/属性/计数语义本身
没问题，问题在于把连续的检测器输出压成了阈值判定。稠密化的做法一一对应：物体存在用该类
最高检测分而非 `score > 0.15`；计数用检测分之和与目标数的距离而非硬比较；颜色用 CLIP
对目标颜色的 softmax 概率而非 argmax；位置用中心偏移量相对容差的连续裕度而非二值关系。
strict 判定保留为评测指标不变。这样组内取值就从 2 个变成 16 个，直接命中上面第 1 条。

## 8. 稠密奖励：GenEval 上第一条正斜率（2026-09-08 11:39）

`geneval_owl` 现在为每个条件报出判定所阈值的那个连续量：检测置信度按判定门限归一、目标
颜色的 CLIP 概率（而非 argmax）、位置的带符号裕度（而非 0.5 穿越）、排除项报 1 减第 n 个
实例的归一置信度。检测在 0.05 的低门限跑，让"差一点"的物体可见；strict 判定仍只看
≥ `detection_threshold` 的框，**在 553 张 anime 评测图上逐题验证 strict/partial/失败原因
完全一致（0 条不同）**，标尺未动。`score_key` 选择读数，训练用 `geneval_owl_dense`。

六条固定题探测（全部同 8 题、16 样本/题）：

| 探测 | 首 → 末 | 标准误 | 斜率 | 斜率 t |
|---|---|---|---|---|

### 8.4 肉眼复核：数字涨了，但一部分是骗过检测器，且有风格漂移

对照图（seed 对齐配对，`outputs/eval_geneval_anime/examples/`）：

**未见过的题里翻盘的 50 条**（`ex_unseen_wins.jpg`，取前 8）。真实的约一半：披萨加书、

ck30 并没有斑马，只是把一个角色画成了斑马耳朵斑马纹；#192"三个杯子"画面里看不到杯子。

**未见过的题里退步的 38 条**（`ex_unseen_loss.jpg`，取前 8）。模式很一致：物体消失
（吹风机、奶牛、胡萝卜、餐桌、人物）与**过量计数**（两个马桶变三个、两列火车变三列、

综合判断：**未见过的题 +0.022（z=1.28）不能当作质量改善**。统计上本来就跨 0，肉眼看
胜负两侧都是"物体在增减"而非"语义更准"，并且存在系统性漂移——丢角色、简化背景、往
"照片棚拍"方向走。这与 OWLv2 是照片域检测器一致：让画面更像照片就能抬高检测置信度。

"稠密奖励能推动策略"，而不是"稠密奖励能提升质量"。长 run 之前必须先加反 hack 的护栏：
锐度作低权重辅助项、把"角色/人物存在"纳入护栏（GenEval 不奖励人物，模型就学会删人物），
并在每个 checkpoint 做肉眼抽查而不只看数字。

## 9. 换到动漫本行：技法遵循（机位 / 取景 / 姿势 / 手臂 / 视线）

§8.4 的结论是 GenEval 的检测器是照片域的，训下去会把 Anima 推离动漫。按 §8.4 提出的四条
性质重新选目标，落到 WD tagger 上：它在 danbooru 上训练，"画得更像照片"在它这里**掉分**。

**`wd_tagger` 也有和 GenEval 判定版一样的粒度病**：`_recall` 先按 0.35 阈值判定再数比例，
每题中位数 6 个标签 → 最多 7 档，组内更少。这解释了 target C 那 43 次更新为什么是平的
（它同时还带着 noise 0.3）。稠密化：每个标签取 `min(prob/threshold, 1)` 再平均——**在阈值处
封顶**，所以已经画对的标签再涨置信度不给分，梯度全部流向缺失的标签，堵掉"刷概率不改语义"
的 hack。两个分数在"每个标签要么缺席要么确信"时完全相等。`score_key` 选读数，训练用
`wd_tagger_dense`，评测用 `wd_tagger_recall`。

**新题库 `dataset/anime_craft`**（2000 训练 / 200 评测，`datasets/danbooru/anime_craft/`）：
从既有 danbooru 语料里挑出同时带 ≥3 个技法标签、覆盖 ≥2 条轴的帖子，prompt 用 Anima 原生的
danbooru 标签格式，评分只算技法标签（发色/瞳色/服装只作上下文不计分），并排除近乎每帖都有的
`full_body` / `looking_at_viewer`。每个目标标签都对 `selected_tags.csv` 校验过。

**base 空间实测**（120 条评测题，干净采样，seed 对齐）：

### 9.1 第一次固定题探测选错了题：GRPO 要的是组内对比，不是绝对难度

`outputs/anima_craft_dense_probe`：`0.412 0.438 0.408 0.410 0.402 0.435 0.417 0.423 0.409 0.416`，
斜率 −0.0002，t = −0.15。**平。**

原因在选题。这 8 条是按"稠密分最低"挑的，也就是最难的，结果半数题里含着 base 几乎从不
产生的标签：`dutch_angle` 与 `head_tilt` 在 120 条评测题上命中率 **0.00**，`arms_behind_back`
0.14、`walking` 0.18。这种标签在 16 个样本里没有一个命中，组内没有差异，advantage 里就没有
指向它的分量——梯度学不到"从没见过的东西"。

**GRPO 消费的是组内对比，单个标签的组内方差约为 q(1−q)，在命中率 q≈0.5 处最大，在 0 或 1
处为零。** 最大空间与最大可学性不是一回事，前者要 q 小，后者要 q 居中。GenEval 那次探测
误打误撞选对了（条件是"判定失败但部分分 ≥ 0.5"，即差一点的题）；这次按最低分选，选到了
q≈0 的死角。

重选：按 `mean q(1−q)` 排序，并剔除任何 q ≤ 0.05 或 ≥ 0.95 的标签所在的题（120 条里 69 条
可用），取前 8（`outputs/probe_craft_contrast8_anime.jsonl`），其余参数逐字不变。
这 8 条的标签是 `from_above` 0.40、`standing` 0.43、`kneeling` 0.44、`leaning_forward` 0.45、
`from_side` 0.65、`looking_up` 0.67、`profile` 0.79、`arm_up` 0.31 的组合。
