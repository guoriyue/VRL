# SPRINT：生产视觉编辑、顺序任务与文字密集页面

状态：实施中（2026-09-22）。用户明确扩大目标到顺序编辑、文字密集图像与漫画。
不替换独立 reward、rollout 准入或 agentic 原目标；补足它们的真实使用场景。
24 小时是投入下限，不以增加实验数量或等待轮次作为交付。

## 已核对的缺口

- `vrl/rewards/models/ocr.py` 的旧单图奖励允许目标子串获得满分；没有区域绑定。
  保留旧配方兼容性，新增区域文字检查，不能把旧 OCR 直接称为漫画 verifier。
- `vrl/rollouts/episodes.py` 的 `VisualTask` 只有固定指令、动作词表和 verifier 文件；
  暂无逐步要求、结构化文字规格、约束保持状态或中断 episode 恢复。
- `vrl/rollouts/visual_adapters.py` 的编辑器确实读取 `observation.current`，具备连续
  编辑的执行基础；重复调用不等于正确完成顺序任务。
- `vrl/rewards/calibration.py` 的冻结组合只有离线 fit/apply/evaluate；训练
  `MultiReward` 只加权主分数。轴、均值、尺度和评分配方须一致，不能只复制权重。
- 当前控制器是有限动作策略；尚未实现任意指令生成、动态工具选择或联合训练。

## 按用户价值推进的工作包

### A. 奖励闭环

同一原始轴分数在离线和训练中使用同一冻结计算；缺轴、配置漂移和非有限值显式失败。
保留每轴贡献与原始评分，不在线自动调权。不把无人工标注的组合称为偏好校准完成。
先确定版本与预处理绑定方式，再接在线聚合；不得绕过现有 Ray/HTTP 隔离与 GPU 停泊。

### B. 文字密集页面

首个实现 `text_regions`：指定画布和区域、每区域预期文字；大小写/标点/额外字保留，
Unicode NFC 与空白归一化明确记录。返回平均、最差区域、精确匹配率和空识别率，
并保存逐区域 OCR 证据。真实 CPU OCR 验证正确/交换/追加/缺失文字。

后续分别检验，不能由一个 OCR 总分代替：

- 多气泡归属与跨气泡阅读顺序；跨格台词不可互换。
- 中英文及混合文字、短词和长段落、数字/标点、竖排；本地只有英文验证时明确限制。
- 字体、字号、对齐、边界溢出、文字与人物重叠；OCR 可读不等于排版合格。
- 场景人物一致性、对白语义、构图与叙事；需要独立视觉判别与人评，不用像素规则假装解决。
- 生成文字与独立排字工具作为不同工具路径比较；保留 native 文字能力的单独评价。

### C. 顺序编辑及约束保持

固定任务例：建立两格页面 → 加指定对白 → 改第二格服装颜色 → 修一个词 → 检查第一格
对白与人物未被破坏。每一步记录父图、指令、新要求、保留要求、输出和各项检查。
把“这次改对”和“之前改好的被破坏”分开报告；测最终成功、逐步满足、约束遗忘、
工具调用、成本、失败率。不重复支付同一终局奖励；新 shaping 必须有清楚的目标定义。
先验证脚本化顺序执行，再测 learned controller；两者成果分别记录。

### D. Agent 编辑与生产运行

保留有限预算、显式停止、完整决策/replay、工具和控制器独立版本。
未来增加局部编辑、裁剪检查、OCR 检查、排字、候选比较和撤销工具时，先定义输入输出、
可重试边界与状态所有权。记录修复循环与成本，不让 judge 分数单独决定成功。
episode 级中断恢复、幂等工具执行、产物生命周期、超时/取消、服务重启、坏样本隔离
分别需要故障注入证据；训练 checkpoint 恢复不自动证明这些已经具备。

## 验收矩阵

| 层 | 必须交付的证据 | 不可冒充的结论 |
|---|---|---|
| 独立奖励 | 真实媒体重评分、版本和各轴诊断、冻结组合线上线下一致 | 没有人评也叫校准完成 |
| 文字区域 | CPU OCR 原图/错位/多字/漏字及结构化报告 | 文字识别正确即漫画质量好 |
| 顺序编辑 | Qwen 多步真实输出与旧约束保持报告 | 多次调用即 agent 学会规划 |
| 策略训练 | 有效梯度、恢复一致、未见来源上的固定策略对照 | loss 降或训练 reward 升即能力提升 |
| 生产可靠性 | 明确作用域的失败恢复、并发/隔离/资源与版本证据 | 单卡短程不崩即所有部署可用 |

## 架构取舍

改变：增加显式文字检查与后续顺序任务契约，复用现有服务和轨迹记录。
保留：模型/transport 分层、reward function 薄适配器、family 接口和现有 OCR 默认语义。
薄适配器是训练/Ray/HTTP 公共边界，保持跨 scorer 一致形状比省行数重要。
协议 schema 名可用常量；任务对白、动作与漫画词汇放数据清单，不硬编码到工作流。
非目标：为了本 sprint 拆 trainer 大文件、另造评分服务、重写采样算法或持续扩展合成训练。

既有 GPU 队列可收尾；新的 GPU 任务必须有明确要回答的问题、数据与预算，且串行排在
现有所有者之后。优先真实编辑与可用奖励闭环，不为填满时间追加训练。
