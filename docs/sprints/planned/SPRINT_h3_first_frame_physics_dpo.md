# SPRINT: MiniMax-H3 固定首帧续写的物理 DPO — 机器人操作视频

**日期**: 2026-10-14  **状态**: 设计；第 0 阶段（示例生成）已排队，等 GPU
**触发**: 用户 "help me design experiment to improve minimax H3 (or ... starting from one fixed image and continue generate video) ... DPO is likely more solid ... data factory for sensitive ... data"
**前置证据**:
- 刚体机械臂实验：283 段 H3 片段中 277 段的刚体拟合误差高于 MuJoCo 参照，中位数 3.53 vs 1.28 px，AUC 0.969（scratch 实验，未入库）。
- DROID 任务统计：倒/擦/舀已有上千条，打蛋/剥皮 0 条，与人接触 3 条（`lerobot/droid_1.0.1` 元数据）。
- DROID 外参加焦距约 110 px（按 320 宽）投影的 Franka 骨架与画面大致重合（ep267、ep745）。
- 仓库 DPO 现状见 §4。

## 0. 目标与一句话假设

**目标**：让 H3 从一张真实机器人场景的首帧（fl2va）续写时，画出的机械臂是可执行的刚体，物体只在被接触后才动，任务真的完成（蛋碎了、水倒进去了）。最终用途是机器人数据工厂。

**假设**：同一首帧、同一提示词、不同随机种子之间，物理质量差异足够大。用"同组最好 vs 最差"构成偏好对，做离线 Diffusion-DPO（LoRA），能在不损伤画质的前提下降低刚体拟合误差、提高任务完成率。

## 1. 为什么先 DPO，不先 GRPO

| | 离线 DPO | 在线 GRPO |
|---|---|---|
| 生成 | 一次性生成，可以利用 GPU 空闲时间分几天攒；偏好对可以反复用 | 每个训练步都要现场 rollout。H3 本机约 5 分钟一段，每组 8 段、每步多个 prompt，本机不可行 |
| 需要的打分 | 只要排序正确，不要求分数尺度可比；自动打分和人工标注可以混用 | 优势值依赖分数尺度，打分噪声直接进梯度 |
| 采样器 | ODE 采样的普通生成即可，不需要 SDE 和 log-prob replay | 需要 SDE 采样加 replay；H3 家族的 GRPO 路径从未用真权重验证过 |
| 稳定性 | beta 加参考模型约束漂移；loss 有界 | 需要 KL、clip、组大小等多项调参 |
| 弱点 | 离线数据，收益容易饱和，要多轮迭代（iterative DPO）；偏好对之间差异多样，模型可能学到伪特征 | 在线探索，上限更高 |

"DPO 只做选择所以更稳"只说对了一半。它确实不依赖奖励的绝对尺度，但会忠实地学习标注里的偏差。我们的刚体实验已经发现一个偏差：运动越少，拟合误差越低。如果不加约束，DPO 会学会"少动"。所以 §3 的偏好构造必须先做硬过滤（运动量、任务完成），再比较物理质量。

**结论**：先在本机做 DPO pilot。GRPO 留到多卡机器到位、奖励通过 §3 的验证之后，作为第二阶段的对照。

## 2. 实验设定

- **条件**：DROID `exterior_1_left` 首帧，320×180 放大裁成 640×384。用 fl2va 生成 124 帧（24 fps）、30 步。
  - 首选机械臂入镜、外参可用的场景，这样刚体打分能用。
  - 已知局限：放大后的首帧偏糊。
- **任务**两类：
  - **真实任务**：DROID 真做过的任务，同一首帧有真机录像，可以做对照。
  - **困难任务**：不可逆或流体操作，DROID 没有：打蛋、撕卷纸、倒满的水或果汁、撕袋子。
- **组**：每个（首帧，提示词）生成 K = 4 段，不同种子。pilot 规模 200 组，即 800 段。
  - 本机约 5 分钟一段，合计约 67 GPU 小时，用空闲时间约 3–4 天。
  - 降到 20 步可以省约 1/3，但第 0 阶段要先确认画质没有明显下降。
- **生成时一并保存**（`latents.pt`）：干净的 `latents`、`audio_latents`、`prompt_embeds`、`text_token_tags`、`condition_latents`。DPO 训练直接读它们，不用重新编码；H3 家族本身也没有视频编码路径。

## 3. 偏好信号（先验证，再用）

每段计算以下信号，排序规则为"先过滤，再比较"：

1. **硬过滤**，不过就直接判负：
   - 首帧一致性：第 1 帧和条件首帧的 LPIPS 低于阈值。
   - 有运动：末端执行器的位移超过下限，防止模型学会"不动"。
   - 机械臂没有变成人手，也没有消失：用 VLM 判断。
2. **任务完成度**：VLM 判断，例如蛋是否碎了、液体是否进了容器。候选：仓库已有的 VideoPhy-2 系列（`vrl/rewards/models/videocon_physics.py`），以及本地 Qwen-VL。
3. **刚体可执行性**：CoTracker 追踪机械臂表面点，在 DROID 外参加拟合内参的相机下做逐帧 IK，取拟合误差（复用 scratch 里的 `armscene.fit_ik`）。拟合出的关节轨迹同时就是动作标签。
4. **接触因果**：物体上的追踪点在夹爪接近之前不应该动（"没碰就动"违规计数）。

5. **第 0 阶段新增的三项**（2026-10-14 第一轮 14 段示例，每段看 8 帧）：
   - **机械臂身份与首帧一致**：首帧里看不到机械臂时，H3 会凭空换成别的机器人。例如擦锅那段是带字样的细长协作臂，打蛋进杯那段前景出现印着 "AMDA" 的巨大连杆。
   - **物体不凭空出现，也不分裂**：撕纸出现半透明的幽灵纸片，撕袋子后留下一个重复的袋子，打蛋进碗时碗里直接多出蛋黄。
   - **不可逆事件确实发生**：两段打蛋都没有画出敲碎的过程。

   另外，放蛋进杯那段末尾，夹爪脱离机械臂悬在空中，刚体打分应该能直接抓到。

   由此加一条首帧约束：第 2 阶段只用机械臂入镜的 DROID 首帧。机械臂不入镜的场景留给 SFT 之后再用。

6. **全部 48 段（10 个首帧任务 ×4 种子）后的修正**：**同组种子之间差异小，失败是系统性的。**
   - 倒杯子、倒水、倒橙汁、舀坚果：4 个种子几乎一样，而且都像样。
   - 机械臂不入镜的场景：4 个种子全都换成了别的机器人。
   - 撕袋子、撕卷纸：4 个种子都出现幽灵物体。
   - 只有"打蛋进碗"在种子间有明显差异，蛋液是否出现、怎么出现各不相同。
   - 首帧 PSNR 的组内差别小于 0.3 dB，不能用来排序。

   因此，只靠"同组最好 vs 最差"凑出的有效偏好对会很少，而且抓不到系统性错误。第 3 阶段要改为三种来源混合：
   - **(a) 扩大组内差异**：每组 8 个以上种子，加上提示词变体（动作描述、速度、细节程度）。
   - **(b) 真实任务用真实视频当胜者**：DROID 录像作为胜者，H3 生成作为败者，类似 SPIN。需要把 DROID 的 15 fps、320×180 视频重采样后过 H3 VAE 编码，并检查域差会不会被模型当成捷径。
   - **(c) 系统性的形态错误先用 SFT 解决**：在 DROID 上微调，DPO 只负责剩下的细节。

**偏好对**：在过完硬过滤的样本里，按"任务完成度优先，其次 3 + 4 的综合分"排序，取最好 vs 最差。综合分差距小于阈值的组丢弃。

**验证门槛（第 1 阶段）**：先用 100 对做人工盲评，用一个网页让用户二选一。只有当每个信号和人工的一致率至少 70%、组合后至少 75% 时，才进入训练。不达标就先改信号。参考 `.claude/skills/reward/qualification.md` 的做法。

## 4. 训练：Diffusion-DPO + LoRA

**仓库现状**（2026-10-14 调查）：
- 只有离线 Diffusion-DPO：`vrl/algorithms/dpo.py:131-144`，默认 `beta=5000`，参考模型 = 关闭 LoRA 后的策略。
- 训练器在 `vrl/trainers/offline/dpo.py`。
- 入口只有 Wan 2.1（`vrl/scripts/families/wan_2_1/train_dpo.py:137-142`）。
- 数据只支持图像对（`[B,6,H,W]`，`vrl/trainers/data/preferences.py:47-53`）。

**H3 缺口**：
- 前向 `forward_step(state, step_idx)` 绑在推理时间表上，不能取任意训练时间步。
- 只支持 t2va，没有 fl2va 条件行（`model.py:396` 的 keyframe 列表为空）。
- batch 固定为 1。
- 不能在单卡上训练。

**两条路线**：
- **A. 仓库外 pilot 脚本（推荐先做）**：直接用 diffusers 的 H3 blocks 构造 fl2va 的打包序列，复用 `latents.pt`，对视频行加噪并只在视频行上算 DPO loss，音频行保持干净。
  - LoRA rank 32，打在 `to_q/k/v/to_out.0`，对齐 `vrl/config/presets/model/minimax_h3/h3.yaml`。
  - transformer 用 group offload 流式上卡，开 gradient checkpointing。
  - 每对 = 策略前向+反向 ×2，加参考前向 ×2。
  - **实测（2026-10-14，§6 第 2 步）**：脚本 `~/h3_local_run/dpo/dpo_probe_small.py`，按真实序列长度测量：视频 9120 行（其中 240 行条件）、音频 414 行、文本 430 token。只加载前 4 个 block，在 40 GB 内存上限下运行，再按比例推算 50 个 block：
    - 每个 block：参考前向 0.06 s，训练前向 0.057 s，反向（含重算）0.151 s；一个 block 的冻结权重 1.2 GB，从普通内存拷到 GPU 要 0.114 s，从锁页内存要 0.027 s。
    - 推算 50 个 block：参考前向约 8.7 s。这和之前用分组 offload 实测的整模型参考前向 8.2 s 吻合，说明推算可信。训练一步约 21.8 s，**一个 DPO 偏好对（一个时间步）约 61 s**，GPU 峰值约 14.5 GB，LoRA 全部 48 个模块都有梯度。
    - 500 对一轮约 8.5 小时，本机可以过夜跑。
  - **两个前提**：
    - diffusers 的分组 offload 只能做推理：前向一结束就把权重搬回 CPU，反向时找不到权重。训练必须自己逐块搬运：反向时把那一块搬回 GPU 重算，LoRA 权重一直留在 GPU 上。
    - 整模型冻结权重在主机上要约 60 GB，而这台机器一共 91 GB。所以训练必须独占机器，并在 `systemd-run --user --scope -p MemoryMax=70G` 下运行；CPU 上每块权重只能留一份，搬回 CPU 时复用这份，不能重新分配。2026-10-14 一个没有内存上限、每次搬运都重新分配的版本，把机器拖到 OOM 重启过一次，后来又被 oomd 杀掉一次。
- **B. 进仓库**：给 `minimax_h3` 家族加 fl2va 条件、任意时间步训练前向、视频偏好对数据集，再把 DPO 入口从 Wan 专用改成家族中立。只有 A 证明有收益之后才做；工作量大，而且需要多卡机器才能跑大于 pilot 的规模。

**超参起点**：beta ∈ {2000, 5000, 10000}；学习率 1e-5；可选 sft_weight 0.1，对胜者做 MSE 以防塌缩；时间步对 sigma 均匀采样。

## 5. 评估

- **留出集**：不同实验室、不同场景的 DROID 首帧，加上训练时没见过的任务描述。
- **主指标**：
  - 刚体拟合误差中位数和 90 分位；
  - VLM 判断的任务完成率；
  - "没碰就动"违规率；
  - 和基线同种子对比的人工盲评胜率。
- **防退化**：
  - 首帧一致性；
  - 画质（美学分加人工抽查）；
  - 通用 t2va 提示词抽样，看是否损伤非机器人内容；
  - 运动量不能下降，防止"少动"作弊。
- **域外检查**：用之前 283 段 MuJoCo 渲染首帧的刚体基准再测一次，看提升能否迁移。
- **消融**：beta；最好 vs 最差，对比所有成对组合；偏好对数量（100/300/500）；是否开 sft_weight；第二轮迭代 DPO（用新模型重新生成、重新打分）。

## 7. 敏感场景数据工厂（应用方向）

扶老人、喂饭、递拐杖这类场景，以及人摔倒、儿童把手伸进工作区、热液体洒出这类危险事件，真实数据很难采，原因包括伦理、安全、隐私和知情同意。生成模型在这里有独特价值，但用途要划清：

- **适合**：
  - 感知训练：识别"人已经伸手准备接"、识别摔倒或危险接近。
  - 策略的安全评估：机器人遇到意外接近时会不会停。
  - 负样本和罕见事件的覆盖。
  - 生成的人物不是真实个体，没有肖像和隐私问题。
- **不适合**：
  - 学习人的真实反应和动力学。生成的人怎么动不是真值，不能当作人体交互的动作标签。
- **必须**：
  - 标注为合成数据，不能当作真实证据；
  - 审计年龄、肤色、残障等分布偏差；
  - 安全相关结论必须在真实或受控实验中复核。
- **实验**：第 0 阶段已包含 4 个辅助任务（t2va）。下一步可以生成"人突然伸手进入工作区"一类片段，测试一个现成 VLM 或安全检测器能否识别。这一步不需要训练 H3。
