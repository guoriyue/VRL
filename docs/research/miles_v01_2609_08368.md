Connector inventory (§2.3): Harbor, NeMo Gym, OpenEnv at the agent boundary;
HUD, Strands and tau-bench at generation; Verifiers at the outer rollout boundary.
AgentENV, Daytona, E2B and Modal supply environments. Integrations are experimental.
The session server lacks image/video input and screenshot recording; VLM support
elsewhere in Miles does not remove that limitation.

Hardware/model inventory (§7): NVIDIA A100 through GB300; ROCm MI300X, MI325,
MI350X and MI355X with unequal CI coverage. The release-day list names Kimi K3,
DeepSeek-V4, GLM-5.2, Qwen3.8, Inkling and Nemotron 3 Ultra; Kimi K3 and Qwen3.8
LoRA are described as open PRs. Additional examples include DeepSeek-V3.2,
Kimi K2.6, Gemma 4, gpt-oss and earlier Qwen/GLM/Nemotron variants. This does
not establish any of those recipes on a consumer Blackwell card.

Other reported measurements and qualifications:

- Optimizer streaming (§3.2.2): actor offload 24→5.2s and reload 8.9→1.3s for
  Qwen3-30B-A3B. These are phase times, not whole-step acceleration.
- OPD (§5.2): response length 14,070→6,132; accuracy 84.0→85.2%, with about
  1.6 percentage-point standard error. The accuracy change is not established.
- Diffusion (§6): LTX-2.3 rollout 157.4→87.6s; step 321.9→252.1s.
  The inspected upstream streaming guide specifies H200 and two consecutive steps.
  Binary transport and parallel parsing changed together; their separate effects are unmeasured.
- Case study (§9): median 263s over the first 30 measured steps; 1,042s warm-up
  clipped; divergence mean 0.0369 over 100 steps; smoothed reward 0.438→0.556;
  prefix cache 96%, about 90–100 actively generating requests out of 128 slots.
  Tool-waiting trajectories retain slots. Each episode has at most 30 turns or one hour,
  each reply at most 8,192 tokens; eight tasks × eight attempts form a training batch,
  with shared-engine evaluation every ten steps. The 78 layers split 18/20/20/20
  across pipeline stages; R3 is off. No claim of statistically demonstrated reward gain.
- True-on-policy (§5.3): zero sampled-token score difference on supported dense
  Qwen3 0.6B/4B configurations. It is not full-distribution equality, does not fix
  stale weights, and costs rollout throughput.
- §3.2.2 mentions DP=4 for the reference run, but §9 and the pinned launcher
  describe DP1/unsharded optimizer state (~279GB/rank). Preserve this discrepancy;
  use the executable launch topology, not a synthesized interpretation.

The paper describes H3 as an open PR. The inspected diffusion HEAD already contains
H3 code and an H3 standard fixture, and its latest commit fixes H3 LoRA IPC naming.

fixture to proof that a complete H3 training curve has been reproduced here.

## VRL gaps, existing owners, and priorities

| Priority | Existing evidence | Action |
|---|---|---|
| P0 | `tests/e2e/test_real_checkpoint_rl.py` checks finite loss/gradients and parity; architecture real-cover labels distinguish doubles | Add exact-recipe evidence and reproducibility records, not a new family allowlist |
| P0 | `vrl/trainers/fsdp.py::normalize_fsdp_parameter_dtype` normalizes parameters; FP32 masters preserve update precision | Audit whether sensitive forward parameters lose necessary precision; masters do not restore forward precision |
| P0 | `vrl/generation/ray/weight_sync.py` verifies installed-version echoes | Reuse driver digest diagnostics and add actual worker-content verification; retain transaction/quarantine behavior |
| P1 | `vrl/rollouts/orchestration/continuous/producer.py`, `vrl/rollouts/orchestration/continuous/queue.py`, `vrl/rollouts/orchestration/continuous/consumer.py` owns finite batches, byte caps, homogeneous versions | Extend the existing three-stage program; do not replace it with Miles' selector |
| P1 | `vrl/scripts/eval/image_checkpoint_eval.py` already pins checkpoint digests and runtime identity | Add delayed-result/run attribution and bounded standalone dispatch only where absent |
| P1 | `vrl/trajectory/builders.py::build_ar_multisegment_trajectory` stores token IDs and old logprobs | Extend existing Janus acceptance with exact per-segment provenance/mask tests |
| Event-gated | Existing transport/provider/agentic programs | Amend them rather than create parallel owners |
| Event-gated | Full-parameter state, MoE policy, matched token teacher, multiple real adapters | Separate parked capacity/OPD/R3/multi-LoRA plans |

The native pipeline is already a typed tensor path. The paper's base64 removal is
not evidence that native VRL currently pays a base64 tax. Its direct applicability is
the external provider boundary; native event-loop and finalization costs need measurement.

The report supports keeping coordinated rollout infrastructure. It neither compares
Ray against rayless nor establishes that a second runtime is required. No Ray migration,
new taxonomy, queue framework, or blanket hardware-support expansion is part of this work.
